# Data Management Plan (DMP)

**Project**: ai-fixed-points
**Owner**: Hugo Bacard (**IJCLab**, hugo.bacard@ijclab.in2p3.fr)
**Version**: 0.1.0 — 2026-11-18

> A lightweight data management plan for an LLM-driven code-improvement tool.
> This project is primarily a **library/tool** rather than a data-producing
> experiment, so the plan below focuses on the small set of data the tool
> touches during development and use.

## 1. Data description

ai-fixed-points reads and writes the following data:

| Dataset / artifact | Type | Where | Sensitivity |
|---|---|---|---|
| Source code being improved | `text/code` | user-provided file, passed at runtime | User's concern; project code is public |
| Configuration | `application/x-yaml` | `config.yaml` (machine-specific, gitignored) | Low — model/profile settings |
| Secrets (API keys) | `application/x-env` | `.env` (gitignored) | **High** — never committed |
| System prompts | `text/markdown` | `prompts/*.md` (committed) | Public |
| Trace / observability logs | `application/json` (Langfuse) | external Langfuse instance | Medium — may contain code under improvement |

## 2. Collection and provenance

- **Source code input**: supplied by the user at runtime (file path or string).
  No automatic collection.
- **Secrets**: supplied locally by the user via `.env`; consumed by
  python-dotenv; resolved through `load_config()` and never stored by the tool.
- **Traces**: generated by Langfuse during agent runs; the tool only pushes
  observation events — it does not persist trace data itself.

## 3. Documentation and metadata

- Configuration is documented in `config.yaml.example` and `docs/`.
- The API is documented in `docs/api.md`.
- Version, authorship, and citation metadata are maintained in
  `CITATION.cff`, `codemeta.json`, and `.zenodo.json` for findability and
  archiving.

## 4. Storage and backup

- Code and prompts: stored in the git repository (`github.com/hbacard/
  ai-fixed-points`), backed up by the hosting platform.
- Secrets: only in the user's local `.env`; the user is responsible for
  backing these up securely (e.g. a password manager).
- Traces: retained per the user's Langfuse instance retention policy.

## 5. Security

- `.env` and `config.yaml` are gitignored (`secret management` indicator).
- No credentials are committed to the repository.
- The `.dockerignore` and `.gitignore` exclude secrets and local config.
- Dependabot keeps dependencies patched (`SECURITY.md` describes how to report
  vulnerabilities).

## 6. Preservation and archiving

- The source repository is archived on **Zenodo** (a DOI badge is displayed in
  the README once the first release is archived), giving long-term, citable
  preservation of each release.
- See also `SUSTAINABILITY.md` and `REPRODUCIBILITY.md` for long-term plans and
  how to reproduce results.

## 7. Responsibilities

- **Data owner / custodian**: Hugo Bacard (project maintainer) is responsible
  for the data management described above.
- **Users**: responsible for the code they feed into the tool and for the
  security of their own API keys.

## 8. Review

This plan will be reviewed at each minor/major release and updated if the
tool's data handling changes (e.g. if it starts storing trace data locally or
producing structured datasets).
